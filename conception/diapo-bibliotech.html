Multi-tenant, isolation par bibliotheque_id
// Pattern appliqué sur tous les endpoints if ($user->getRole() !== 'super_admin' && $entity->getBibliothequeId() !== $user->getBibliothequeId()) { return $this->json([ 'code' => 'ACCESS_DENIED' ], Response::HTTP_FORBIDDEN); }
Principe SaaS
Une seule instance d'API, une seule base de données PostgreSQL.
Chaque bibliothèque a ses données isolées par bibliotheque_id au niveau applicatif.
Le super_admin (BiblioTech) a un accès cross-tenant (bibliotheque_id null).

Choix de modélisation
Catalogue global + exemplaires séparés : évite la duplication des métadonnées. Un livre = une entrée, le stock par bibliothèque dans exemplaires.

ON DELETE RESTRICT sur les FK critiques : empêche la suppression d'une bibliothèque avec des prêts actifs.

Normalisation 3NF, aucune dépendance transitive.

Sécurité · Authentification
JWT RS256 + Refresh Token rotation
Algorithme
RS256
RSA 4096-bit keypair
Access Token TTL
8 h
28 800 secondes
Refresh Token TTL
30 j
Token opaque rotation
Brute-force
5 / 15'
Verrou compte + rate limiter IP
Mots de passe : Argon2id
# security.yaml password_hashers: App\Entity\Utilisateur: algorithm: argon2id memory_cost: 65536 # 64 Mo time_cost: 4 # 4 itérations
Flux d'authentification
POST /api/login → JWT + RefreshToken
POST /api/token/refresh → nouveau JWT (rotation)
POST /api/logout → révocation RefreshToken
Double protection anti-brute force
Rate limiter IP (Symfony Limiter) :
→ 10 tentatives / 5 minutes par IP

Verrou compte (base de données) :
→ 5 tentatives échouées → lockedUntil +15 min
→ Champ loginAttempts + lockedUntil sur l'entité
RefreshToken, entité custom
Token opaque 32 bytes (hex). Stocké en base. Rotation à chaque usage : l'ancien token est supprimé, un nouveau est émis. Révocation immédiate sur logout.

API externe · Décision prise en phase de déploiement
Migration Google Books → Open Library
Google Books API — Abandonnée
Problème découvert en production : le qualificatif isbn: retourne systématiquement totalItems: 0 pour tous les ISBNs, y compris des livres très connus.
isbn:9782070360024 → 0 résultat
isbn:9780141439518 → 0 résultat
Titre seul → 338 résultats ✓ (clé valide)
Diagnostic : limitation non documentée de l'API
Flux (inchangé côté bibliothécaire)
1. Le bibliothécaire saisit un ISBN dans le catalogue
2. GET /api/livres/isbn/{isbn} → OpenLibraryService
3. Pré-remplissage : titre, auteur, éditeur, année, couverture
↳ ISBN introuvable → formulaire vide pré-rempli avec l'ISBN
Open Library API — Retenue
Gratuite, sans clé API
Catalogue mondial 37 M+ livres
ISBN-13 et ISBN-10 supportés
Couvertures via covers.openlibrary.org
Pas de quota, pas de 429

Difficultés surmontées
Isolation multi-tenant incomplète
14 endpoints sans vérification bibliotheque_id. Résolu par audit systématique contrôleur par contrôleur.
JWT stateless vs garde applicative
La logique must_change_password ne peut pas être dans le token (stale). Solution : vérification à chaque navigation dans ProtectedRoute.
Docker Compose paths relatifs
Les chemins ./backend depuis dev/docker/ étaient invalides. Corrigés en ../backend.
Rate Limiter Symfony : injection
L'injection #[Target('loginIp')] nécessite une syntaxe spécifique Symfony 7, non documentée avec LexikJWT.
